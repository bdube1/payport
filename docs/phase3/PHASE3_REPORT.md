## What was built

**Reconciliation** (`recon` package, V40):
- Statements are imported once. The same provider and file hash is the same statement, whatever the file name.
- Lines are matched by our reference (attempt suffixes included), the provider reference or the attempt references.
- Categories:
  - MATCHED;
  - MISSING_IN_PAYPORT;
  - STATUS_MISMATCH (the provider was paid but PayPort recorded a failure or timeout, which also catches late payments);
  - DUPLICATE;
  - AMOUNT_MISMATCH;
  - CURRENCY_MISMATCH (ZiG and ZWG are treated as the same);
  - TIMING (outside the window, or expected in the next statement);
  - MISSING_IN_STATEMENT.
- Every difference is a `recon_exceptions` row with evidence. Raising one is idempotent.
- Resolution is a person's recorded decision, with a note. "Honoured" can only come from the approved late-payment action.
- Live lifecycle conflicts use the same queue: PAID_AFTER_TIMEOUT, PAID_AFTER_FAILURE, FAILED_AFTER_PAID, PAID_ON_SUPERSEDED_ATTEMPT.
- Formats:
  - the existing provider parsers (EcoCash, OneMoney, O'mari, NetOne, Telecel, InnBucks);
  - PayPort's generic CSV.

**Settlement** (`settlement` package, V40):
- **Eligible funds:**
  - live, paid checkout sessions;
  - older than the hold (24 h);
  - with the payment MATCHED on a provider statement;
  - not claimed by another batch;
  - in LIVE mode, not settled by the legacy settlement.

  Refunds are prorated in integer minor units, rounded half-up.
- **Batches:**
  - DRAFT → APPROVED → INSTRUCTED → COMPLETED (or CANCELLED).
  - One approver, or two above `SETTLEMENT_DUAL_APPROVAL_THRESHOLD_MINOR`.
  - The creator never approves, and nobody approves twice.
- **Payout file:** generated by a `PayoutFileAdapter`. The interim format is a documented CSV until the sponsor bank's format is known. Instruction references are fixed per item and unique.
- **Bank results** (PAID / RETURNED / FAILED) are applied from a file, whose hash is the proof. A returned or failed payout releases its sessions, so they become eligible again.
- **Modes:**
  - **PARALLEL** (default): batches can be drafted, approved and compared with the legacy settlement (`legacyComparison`), but never instructed. The database enforces this too.
  - **LIVE**: the legacy scheduler stops, and batches can be instructed.

## Not done / dependencies
- **The sponsor bank's payout format and API.** The CSV adapter is a placeholder behind an interface.
- **Real provider statement samples** to validate the parsers. The generic CSV works today.
- **Ledger postings for settlement** (payable → settlement payable → bank). These wait for shadow-ledger parity (E5) and then the cutover. Eligibility comes from the gateway's sessions, like the legacy settlement.
- **Provider refund APIs** (EcoCash refund, OneMoney refund, O'mari void) for late payments. Refunds are recorded, not executed.
- **Retiring the legacy settlement.** Needs your sign-off after a parallel-run period (`SETTLEMENT_MODE=LIVE`).
