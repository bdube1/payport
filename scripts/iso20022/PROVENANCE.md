# ISO 20022 schema provenance

iso20022.org refuses downloads from CI runners ("403 SWIFT site off-line"), so the schemas are kept in
the repository and verified against `schemas.sha256` on every CI run (`fetch-schemas.sh`).

|---|---|---|---|

Kept in this private repository for internal validation; do not publish it or ship it to third parties. |

**Replace the base copies with files downloaded from iso20022.org** when convenient (message archive:
camt.053.001.08 = message 12736, pain.001.001.09 = 14346, pain.002.001.10 = 14396). If the content is the
same the tests are unaffected; update the pins in the same commit.

**How they are used:** every message is validated against the base schema. A market can additionally
require its bank's usage guideline (`statement_guideline` in the market settings, set from the ops
console); a statement must then pass both. The HVPS+ guideline is stricter than the base schema (for
example: only booked entries, statement pagination required, date-times with a UTC offset, no
remittance information in entry details), so only switch it on when the sponsor bank confirms it uses it.
